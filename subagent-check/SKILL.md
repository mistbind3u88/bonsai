# subagent-check

サブエージェント起動前の状態確認を行い、新規起動してよい状態かを判定する。サブエージェントの起動そのものは呼び出し元スキルが行う。

## 手順

### 1. 現在のサブエージェント状態を確認する

現在のセッションで把握できるサブエージェントについて、以下を確認する。

- agent id / nickname
- 実行中、完了、停止などの状態
- 担っている役割や依頼内容
- 呼び出し元スキルが必要としている役割との重複
- 起動上限に対する余剰

起動上限の余剰は、実行環境が表示しているサブエージェント一覧、完了通知、実行中エージェント数、起動失敗メッセージから判断する。上限値を直接取得できる手段がない環境では `available_slots: unknown` とし、`OK` ではなく `REUSE` / `WAIT` / `ASK_USER` のいずれかを返す。

### 2. 完了済みサブエージェントを整理する

完了済みのサブエージェントがある場合は、実行環境で利用できる結果取得操作で結果を回収して要点を保持する。役割を終えたものは、実行環境で利用できる終了・close 操作で閉じて、起動枠を空ける。

結果をまだ使う可能性がある場合は、閉じる前に必要な情報を呼び出し元へ報告する。

### 3. 再利用可否を判断する

既存サブエージェントが呼び出し元の目的に合う場合は、新規起動より再利用を優先する。

再利用できる条件:

- 依頼したい観点や対象が既存サブエージェントの役割と一致している
- 既存サブエージェントが同じコードベースや同じ文脈を扱っている
- 追加依頼によって現在の作業を妨げない

### 4. 起動可否を返す

以下の形式で、呼び出し元に判定結果を返す。

```text
subagent-check:
  status: OK | REUSE | WAIT | ASK_USER
  completed_agents: <結果回収・close 判断>
  reusable_agents: <再利用候補>
  available_slots: yes | no | unknown
  recommendation: <呼び出し元が次に取る行動>
```

判定基準:

- `OK`: 新規サブエージェントを起動する余剰がある
- `REUSE`: 目的に合う既存サブエージェントを再利用する
- `WAIT`: 実行中サブエージェントの完了待ちが妥当
- `ASK_USER`: 起動上限や再利用判断が不明確で、ユーザー確認が必要

## 呼び出し元スキルの扱い

サブエージェントを起動するスキルは、起動直前に `/subagent-check` を実行する。

- `OK` の場合: 呼び出し元スキルが新規サブエージェントを起動する
- `REUSE` の場合: 呼び出し元スキルが既存サブエージェントへ追加依頼する
- `WAIT` の場合: 呼び出し元スキルが完了通知を待ってから再判断する
- `ASK_USER` の場合: 呼び出し元スキルが状況と選択肢を報告し、ユーザー判断を待つ

## 注意

- このスキルは起動前チェックだけを担う
- サブエージェントへの本依頼内容は呼び出し元スキルが管理する
- 完了済みサブエージェントの結果は、閉じる前に必要な情報を要約して保持する
