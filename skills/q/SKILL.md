# q

質問へ回答するための確認専用スキル。現在分かっていることを整理する。

## 手順

### 1. 質問の対象を特定する

ユーザーの質問が何に対するものかを特定する。

- これまでの会話や作業経緯
- 明示された前提、判断、合意
- 現在のリポジトリ状態
- 特定の skill、ドキュメント、差分、コミット

対象が曖昧で、回答に影響する解釈が複数ある場合は、解釈を明示して答える。必要なら短く確認する。

### 2. 事実・推測・未確認を分ける

回答前に、次を分けて整理する。

- 明示された事実: ユーザー発言、既存ファイル、コマンド結果、コミット履歴などで確認できること
- 推測: 状況から考えられるが、直接確認していないこと
- 未確認: 追加確認が必要なこと

推測を事実として書かない。未確認のまま答える場合は、その範囲を明示する。

### 3. 必要な read-only 確認だけ行う

リポジトリ状態や差分が回答に必要な場合だけ、read-only の確認を行う。

```bash
git status -s
git log --oneline <range>
git diff --stat <range>
```

ファイル内容の確認が必要な場合は `Read` / `Grep` / `Glob` を使う。

### 4. 回答する

回答は、質問に直接答えることを優先する。必要に応じて以下の順に整理する。

1. 結論
2. 根拠
3. 未確認または注意点

事実として確認できていない内容は、推測または未確認として明示する。

## 出力

簡潔に答える。根拠が重要な場合は、確認したファイルやコマンド結果を添える。

```text
結論:
...

根拠:
- ...

未確認:
- ...
```

単純な質問では、上記の見出しを省いてよい。
