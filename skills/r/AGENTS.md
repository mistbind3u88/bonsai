# r

## 前提ツール

- [git](https://git-scm.com/)

## 責務の境界

- 指定されたドキュメント、ルール、差分、コミット、会話上の前提を read-only で読み直し、現在の理解を更新する。
- 読み直しに必要な範囲で `Read` / `Grep` / `Glob` と read-only の git コマンドを使う。
- 質問への回答が主目的になった場合は `/q`、企画・開発相談の論点整理が主目的になった場合は `/d` を案内する。
- ファイル編集が必要な場合は、目的に応じて `/doc-sync`、`/wiki-sync`、または対象作業の skill を案内する。
- commit / amend / fixup が必要な場合は `/commit` または `/fixup`、push が必要な場合は `/push` を案内する。
- GitHub Issue / PR の状態確認は `/gh-read`、GitHub 投稿は目的に応じて `/gh-edit`、`/diff-comment`、`/pr-progress`、`/reply-review` を案内する。
- ファイル編集、Issue / PR 作成、commit、push、サブエージェント起動が必要な場合は、対応する skill と確認事項を案内する。

## 読み直し方針

- 読み直した対象、更新された理解、以前の理解との差分、注意点、未確認事項を分ける。
- 以前の説明や会話上の前提とズレた点は、何がどう変わったかを明示する。
- 推測は推測として扱い、確認できた事実と分けて報告する。
