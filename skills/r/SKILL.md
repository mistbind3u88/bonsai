# r

指定された資料や前提を読み直し、以後の作業で使う現在の理解を更新する。

`q` が質問への回答、`d` が議論開始時の論点整理を担うのに対し、`r` は「指定対象を読み直して理解を更新する」ことに責務を限定する。

## 手順

### 1. 読み直す対象を特定する

ユーザーが指定した対象を確認する。

- 特定のファイル、ディレクトリ、glob
- `AGENTS.md` / `CLAUDE.md` / `README.md` / `SKILL.md`
- 既存 skill、テンプレート、タスクドキュメント
- 差分、コミット、直近の作業履歴
- 会話上の前提、以前の説明、合意事項

対象が曖昧で、読み直す範囲によって結論が変わる場合は、暫定範囲を明示して進める。範囲の選択が必要な場合は、判断に影響する候補を短く示して確認する。

### 2. read-only で確認する

必要な範囲だけ read-only の確認を行う。

```bash
git status -s
git log --oneline <range>
git diff --stat <range>
git diff <range>
git show <commit>
```

ファイル内容の確認が必要な場合は `Read` / `Grep` / `Glob` を使う。

外部情報、GitHub 状態、ファイル編集、commit、push が必要な場合は、必要な次の skill と確認事項を示す。

### 3. 現在の理解を更新する

読み直した内容を、次の観点で整理する。

- 維持する理解
- 更新された理解
- 以前の説明、前提、記憶とズレた点
- 今後の作業で注意すべき点
- 未確認として残る点

以前の理解や会話上の前提が誤っていた場合は、何がどう変わったかを明示する。推測は推測として区別する。

### 4. 以後の作業で使う前提を示す

読み直し後に使う前提を短くまとめる。必要に応じて、次に使う skill を案内する。

ファイル編集、Issue / PR 作成、commit、push、サブエージェント起動が必要な場合は、対応する skill と確認事項を案内する。

## 出力

必要に応じて以下の形で報告する。

```text
読み直した対象:
- ...

更新された理解:
- ...

以前の理解との差分:
- ...

注意点:
- ...

未確認:
- ...

次に使う skill:
- 必要な場合だけ記載
```

単純な読み直しでは、見出しを減らしてよい。

## 責務外の扱い

- 質問への回答が主目的になった場合は `/q` を案内する。
- 企画・開発相談の論点整理が主目的になった場合は `/d` を案内する。
- GitHub Issue / PR の状態確認が必要な場合は `/gh-read` を案内する。
- ファイルの作成・編集が必要な場合は、目的に応じて `/doc-sync`、`/wiki-sync`、または対象作業の skill を案内する。
- commit / amend / fixup が必要な場合は `/commit` または `/fixup` を案内する。
- push / force push が必要な場合は `/push` を案内する。
- サブエージェント確認が必要な場合は、起動前確認を含む該当 workflow skill、または `/subagent-check` から始めるよう案内する。
