# rule-check サブエージェント依頼テンプレート

以下を埋めて、サブエージェントへ渡す。

## 境界確認

- 実行中のスキル: `/rule-check`
- 依頼する役割: 適用ルールと対象差分の照合
- サブエージェントが返すもの: ルール単位の `OK` / `対象外` / `要修正` と、要修正時の根拠・修正方針
- メインエージェントが担うもの: スキル進行、最終判断、修正方針の採否、`mark`、ユーザー報告

## 検査対象

- リポジトリ: `<absolute-repo-path>`
- 比較元: `<base-ref-or-sha>`
- 比較先: `<head-ref-or-sha>`
- 変更ファイル: `<changed-files>`
- 適用ルールファイル:
  - `<applicable-rule-files>`
- 明示的に参照すべき文書・URL・review-log 関連 ID:
  - `<reference-path-url-or-none> — <why-this-reference-matters>`
- ユーザーが明示した確認範囲・変更概要: `<user-provided-scope-or-none>`

適用ルールファイルと明示参照を読み、変更ファイルに実際に適用されるルールを抽出する。その後、差分と変更ファイルを読み、抽出したルールへの適合を判定する。明示参照は、ルールの適用範囲や判断根拠として優先して確認する。ドキュメントの内容が変更に追従しているかは `/doc-check` の担当とし、ここではルールに定義された必須条件、禁止事項、品質基準、手順、配置基準に合っているかを判定する。

## 検査観点

固定の必須ルールを前提にせず、適用ルールから実際の確認項目を作る。確認項目は以下の分類で整理してよい。

| 分類             | 読み取る内容の例                                                                         |
| ---------------- | ---------------------------------------------------------------------------------------- |
| 適用範囲         | どのファイル・ディレクトリ・作業種別にどのルールが適用されるか                           |
| 変更スコープ     | 変更対象、管理対象外、生成物、秘匿情報、外部依存情報の扱い                               |
| 実装品質         | テスト、lint、build、設計層、production / test code の境界、環境前提の扱い               |
| コード品質       | 対象リポジトリのルールに定義された設計、責務分離、命名、エラー処理、互換性、レビュー観点 |
| コマンド・権限   | shell 実行、外部サービス、sandbox 外実行、認証情報、ユーザー承認の扱い                   |
| Git / GitHub     | branch、commit、push、force push、PR / Issue / comment、CI 監視の扱い                    |
| ドキュメント配置 | ルールに定義された文書種別、配置先、コード近傍コメント、タスク文脈、Wiki への情報配置    |
| ドキュメント品質 | ルールに定義された言葉選び、読み手、粒度、構成、表記、例示、禁止表現、必須表現           |
| workflow 境界    | 複数手順の責務分担、委譲、サブエージェント利用、結果回収、最終判断の扱い                 |
| 記述スタイル     | 肯定形、曖昧語、読み手、Issue / PR / docs の書き方に関するルール                         |
| 既存ルール矛盾   | 追加・変更された手順や説明が、上位または近傍の既存ルールと整合しているか                 |

## 出力形式

```text
観点別結果:
  適用範囲:
    判定: OK
    根拠: <確認したルールファイルと適用範囲>
  変更スコープ:
    判定: 対象外
    根拠: <該当ルールがない、または差分に該当しない理由>
  実装品質:
    判定: 要修正
    ファイル: <path>
    適用ルール: <rule summary>
    参照: <確認したルールファイル・URL・review-log 関連 ID>
    修正方針: <必要な対応>
  コード品質:
    判定: OK
    根拠: <確認したコード品質ルール>
  ドキュメント品質:
    判定: OK
    根拠: <確認したドキュメント品質ルール>
```

`要修正` がない場合も、検査観点にある分類ごとに `OK` または `対象外` を明示する。分類は、適用ルールがない場合も省略せず `対象外` として扱う。
