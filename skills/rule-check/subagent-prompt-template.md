# rule-check サブエージェント依頼テンプレート

以下を埋めて、サブエージェントへそのまま渡す。

## 境界確認メタ情報

- 実行中のスキル: `/rule-check`
- 依頼境界: メインエージェントが `/rule-check` を実行中であり、サブエージェントの役割は指定観点での読み取り検査結果を返すこと
- メイン側に残す判断: サブエージェント検査結果の最終判断、要修正時の対応方針、`mark`、ユーザーへの最終報告
- サブエージェントが行うこと: 対象差分と適用ルールを読み、観点別に `OK` / `対象外` / `要修正` を返す
- サブエージェントがメイン側に残すこと: スキル実行、ファイル編集、`mark`、commit、push、ユーザーへの最終判断

## 検査対象

- リポジトリ: `<absolute-repo-path>`
- 比較元: `<base-ref-or-sha>`
- 比較先: `<head-ref-or-sha>`
- 変更ファイル: `<changed-files>`
- 適用ルール:
  - `<applicable-rule-files>`
- ユーザーが明示した確認範囲・変更概要: `<user-provided-scope-or-none>`

サブエージェントは、メインエージェントが指定した適用ルールを読み、呼び出し元リポジトリで実際に適用される検査観点を抽出する。そのうえで比較元・比較先の差分と変更ファイルを読み取り、変更内容が抽出したルールへ適合しているかを確認する。

## 検査観点

以下は固定の必須ルールではなく、適用ルールから検査観点を抽出するための分類軸である。対象リポジトリの `AGENTS.md` / `CLAUDE.md` に該当ルールが存在する場合だけ、そのルールへの適合を判定する。

| 観点カテゴリ           | 読み取るルールの例                                                                                 |
| ---------------------- | -------------------------------------------------------------------------------------------------- |
| 適用ルールの網羅       | 変更ファイルに適用される `AGENTS.md` / `CLAUDE.md` が確認対象に含まれているか                      |
| 変更スコープ           | 変更してよい領域、対象外の領域、業務固有知識や秘匿情報の扱い                                       |
| コマンド・権限         | `allowed-tools`、shell 実行、sandbox 外実行、外部サービス利用、最小権限                            |
| Git / GitHub 操作      | branch、commit、push、PR / Issue / comment、force push、CI 監視                                    |
| ドキュメント配置       | README、`AGENTS.md`、`CLAUDE.md`、タスクドキュメント、LLM Wiki、コードコメントへの配置基準         |
| スキル / workflow 境界 | skill の分類、MECE、委譲、循環参照、サブエージェント利用境界、mark の扱い                          |
| 実装品質               | テスト、lint、build、DB / repository 層、production / test code の境界、環境前提の扱い             |
| 記述スタイル           | 肯定形の手順記述、Issue / PR / docs の書き方、曖昧語の扱い、読み手やレビュー観点に関するルール     |
| 既存ルールとの矛盾     | 変更内容、追加ドキュメント、追加手順が、ルートまたはディレクトリ固有の既存ルールと矛盾していないか |

## 出力フォーマット

観点別に `OK` / `対象外` / `要修正` を示す。`OK` は該当ルールが存在し、変更内容が適合している場合に使う。`対象外` は該当カテゴリのルールが適用ルール内に存在しない場合に使う。`要修正` の項目は該当ファイル、適用ルール、修正方針を添える。

```text
観点別結果:
  適用ルールの網羅:   OK
  変更スコープ:       対象外
  コマンド・権限:     OK
  Git / GitHub 操作:  対象外
  ドキュメント配置:   OK
  スキル / workflow 境界: OK
  実装品質:           OK
  記述スタイル:       OK
  既存ルールとの矛盾: OK
```

自由記述の所感は不要。`要修正` がない場合も、上記フォーマットで `OK` または `対象外` を明示する。
