# link-agentdoc

## 前提ツール

- [git](https://git-scm.com/)

## 責務の境界

- `AGENTS.md` / `CLAUDE.md` へ、恒久的に参照すべきドキュメントの link、delegate、ref を追記する。
- 参照先をセクション相当として扱うか、役割分担の委譲先として扱うか、末尾の参考として扱うかを判定する。
- 参照先本文の作成・大幅更新は `/doc-sync` または `/wiki-sync` へ案内する。
- タスクドキュメントの配置先確認は `/taskdoc-locate` へ案内する。
- 追記後のルール適合検査は `/rule-check` へ案内する。

## 3 つの導線分類

`link` は、実行者が直接読むべき単一ドキュメントを `AGENTS.md` / `CLAUDE.md` のセクション相当として `@...` link で扱う場合に使う。次の条件に当てはまる場合は `link` を選ぶ。

- `AGENTS.md` / `CLAUDE.md` の詳細説明、判断基準、運用手順の一次情報源である。
- 参照理由を「何を判断するために読むか」として一文で説明できる。
- リポジトリ内の安定したファイルである。
- `@...` を自動展開する環境では参照先を直接読ませ、自動展開しない環境では見出しと `@...` の参照先から読むべきファイルを判断できる。
- 本文へ全文を書くより、見出しとリンクでセクションを分ける方が読みやすい。
- 参照先から元の `AGENTS.md` / `CLAUDE.md` へ戻る導線がなく、相互参照・循環参照を作らない。

`delegate` は、対象 `AGENTS.md` / `CLAUDE.md` と委譲先ドキュメントで役割を分け、より詳細を Markdown link で伝える場合に使う。次の条件に当てはまる場合は `delegate` を選ぶ。

- 対象 `AGENTS.md` / `CLAUDE.md` には基本方針や読む順序を置き、詳細な判断基準や対象一覧を委譲先に置く。
- 作業者が冒頭で、どの情報をこのファイルで読むか、どの情報を委譲先で読むかを判断する必要がある。
- 委譲先の内容が作業前提に近く、末尾の参考一覧では発見が遅い。
- 委譲先から対象 `AGENTS.md` / `CLAUDE.md` へ戻る導線を置く場合は、相互参照の役割を明記し、同じ判断を往復して読ませる循環参照を作らない。

`ref` は、関連ファイルを探す起点になるディレクトリ、glob、候補群を Markdown link として末尾にまとめる場合に使う。次の条件に当てはまる場合は `ref` を選ぶ。

- 複数ファイルから該当するものを探す必要がある。
- ディレクトリ、glob、命名規則、候補群を示したい。
- 公式仕様や恒久的な外部 URL を参考として示したい。
- ファイルが増減しやすく、個別リンクの列挙が重複管理になりやすい。
- 実行者に「必要に応じてこの配下を確認する」という探索行動を促したい。

## 本文に直接書く基準

短い必須ルールはリンクやパスだけにせず、`AGENTS.md` / `CLAUDE.md` 本文へ直接書く。詳細が長い場合は、本文に要点を置き、`link` または `delegate` で詳細へ誘導する。

## 追記する基準

- 参照先が現在の `AGENTS.md` / `CLAUDE.md` の適用範囲に入っている。
- 実行者が作業開始時または判断時に読む価値がある。
- 参照先の内容が一時的な PR 固有文脈ではなく、将来の作業でも使える。
- 既存の同じ導線がなく、追加によって重複管理が増えない。

## 重複を防ぐ基準

- 同じドキュメント、URL、探索起点は `link` / `delegate` / `ref` のうち読み手が最初に判断すべき 1 つの分類に集約する。
- 同じ参照先が既にある場合は、新しい導線を追加する代わりに既存導線の見出し、説明、配置、分類を更新する。
- `link` と `ref` が同じ参照先を指す場合は、実行者が必ず読むべき単一ドキュメントなら `link`、探索起点や参考候補なら `ref` に統合する。
- `delegate` と他分類が同じ参照先を指す場合は、対象 `AGENTS.md` / `CLAUDE.md` と委譲先の役割分担を冒頭で説明する必要があるときに `delegate` へ統合する。
- 親ディレクトリの `ref` と配下ファイルの `link` / `delegate` は、読む目的が違う場合だけ併存させ、それぞれの説明に探索起点と必読文書の違いを書く。

## 追記を見送る基準

- 一時的なタスクメモ、会話ログ、未コミットのローカルファイルは、恒久導線として追記せず、必要な文脈をタスクドキュメントや PR / Issue 本文に残す。
- 特定 PR / Issue だけで必要な文脈は、対象 PR / Issue かタスクドキュメントに記載する。
- 参照理由を一文で説明できない場合は、先に参照先本文の役割を `/doc-sync` または `/wiki-sync` で整理する。
- `AGENTS.md` / `CLAUDE.md` の適用範囲外である場合は、適用範囲に合う agent doc を対象にする。
- 同じ内容が既に近いセクションで参照されている場合は、新規導線を増やさず既存説明を補足する。
