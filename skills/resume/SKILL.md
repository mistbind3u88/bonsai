# resume

レートリセットや一時中断の後に、同じ作業を再開するための初手プロンプトを整える。

このスキルは、別セッションへの移管や担当交代ではなく、**再開直後の状況把握を速くすること**に責務を限定する。

## 引数

```text
$ARGUMENTS: <覚えている状況や再開時に伝えたい補足>
```

引数は任意。ユーザーが覚えている中断理由、未完了事項、注意点があれば受け取る。引数がなくても、ローカルで確認できる範囲から再開用プロンプトを組み立てる。

## 手順

### 1. 再開対象を特定する

次の情報から、何の作業を再開するかを特定する。

- 現在の会話で明示された作業目的
- `$ARGUMENTS` に含まれる補足
- 現在のブランチ名や作業ディレクトリ

必要に応じて、次の read-only コマンドで現在の作業位置を確認する。

```bash
git rev-parse --abbrev-ref HEAD
git status -s
```

対象が曖昧な場合は、複数解釈を混ぜず、どの解釈でまとめるかを明示する。解釈の違いで再開内容が大きく変わる場合は、必要最小限の確認だけ行う。

### 2. 事実として確認できる情報を集める

必要な範囲だけ read-only で確認する。

```bash
git rev-parse --abbrev-ref HEAD
git status -s
git log --oneline -10
git diff --stat
```

`git diff --stat` は未コミットの変更量を把握するために使う。ユーザーが比較対象のブランチ名やコミットを明示した場合だけ、必要に応じて `git diff --stat <target>..HEAD` を使って現在のブランチ進捗を補足してよい。

必要に応じて `Read` / `Grep` / `Glob` で関連ファイルやメモを確認する。

確認対象の例:

- 未コミットの変更
- 直近のコミット履歴
- 関連ファイルやドキュメント
- ユーザーが明示した制約や注意点

### 3. 事実・推測・未確認を分ける

再開用プロンプトへ入れる前に、内容を次の3区分へ分ける。

- 事実: コマンド結果、既存ファイル、ユーザーが明示した内容
- 推測: 状況から考えられるが直接確認していない内容
- 未確認: 再開判断に影響するが確認できていない内容

推測を事実として書かない。確認できていないことは、欠落したままにせず `未確認` として残す。

### 4. 次にやるべき一手を整理する

再開後に最初に着手すべき行動を1つか2つに絞る。

次の観点で整理する。

- 既に終わっていること
- 未完了の作業
- 再開直後に確認すべき点
- その後の最初の実装・確認・調査

複数候補がある場合は、優先順位と理由を短く付ける。

### 5. 再開用プロンプトを生成する

次の形式で、再開時にそのまま貼れるプロンプトを生成する。

```text
この作業を再開したいです。

目的:
- ...

現在の状態:
- ...

完了済み:
- ...

未完了:
- ...

次にやってほしいこと:
- ...

注意点:
- ...

未確認:
- ...

参照してほしいファイル:
- ...
```

必要に応じて、このプロンプトの前に人間向けの短い要約を添えてよい。

## 出力

以下の順で簡潔に返す。

```text
resume:
  要約:
  - <再開状況の短い要約>
  再開用プロンプト:
  <そのまま使える本文>
  未確認:
  - <なければ「なし」>
```

## 注意

- このスキルは再開用プロンプトの生成に限定する。コード変更、Issue / PR 更新、push、担当交代の判断は行わない
- 前回会話の完全再現を目指さない。再開判断に必要な情報へ圧縮する
- ユーザーが覚えている内容とローカルで確認できる内容が矛盾する場合は、どちらを事実として扱ったかを明示する
