# revise

直前のエージェント提案に対するユーザーの差し戻し、条件追加、別案要求を受け取り、再検討すべき論点を整理する。

## 手順

### 1. 再検討対象の提案を特定する

会話中の直前のエージェント提案から、ユーザーが見直しを求めている対象を特定する。複数の選択肢や段階的な提案がある場合は、どの部分が差し戻されたかを分けて読む。

### 2. 否定された要素を分解する

ユーザー応答から、何が問題視されたかを分解する。少なくとも次の観点で見る。

- 前提
- 手順
- 制約
- 実行順
- 代替案の要求

条件付き承認のように見える場合でも、新しい条件が追加されているなら再検討要求として扱う。

### 3. 再提案に必要な論点を整理する

次を整理する。

1. どの提案が差し戻されたか
2. どの前提や手順を変える必要があるか
3. 再提案時に守るべき条件
4. まだ未確認の点

### 4. 結果を返す

以下の形で簡潔に返す。

```text
revise:
  差し戻し対象: <どの提案が再検討対象か>
  見直す点:
  - <前提・手順・制約のどこを変えるか>
  再提案時の条件:
  - <守るべき条件。なければ「なし」>
  未確認事項:
  - <追加で確認が必要な点。なければ「なし」>
```

## 注意

- このスキルは差し戻し内容を整理する。実際の再提案や実装は後続のエージェント判断で行う
- 単なる承認で条件追加がない場合は、このスキルではなく `approve` の対象とする
- 否定対象が曖昧なまま勝手に前提を補わない
