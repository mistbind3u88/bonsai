# gh-edit サブエージェント依頼テンプレート

以下を埋めて、GitHub 投稿前の概要欄本文レビューとしてサブエージェントへ渡す。

## 境界確認

- 実行中のスキル: `/gh-edit`
- work_unit: `gh-edit:<owner>/<repo>#<number-or-new>`
- role: `pr-body-review`
- reuse_policy: `prefer-reuse`
- 依頼する役割: PR / Issue 概要欄本文ソースの文面検査
- サブエージェントが返すもの: 観点別の `OK` / `対象外` / `要修正` と、要修正時の根拠・修正方針
- メインエージェントが担うもの: ソースファイル編集、GitHub 投稿、最終判断、ユーザー報告

## 対象

- 対象種別: `<PR|Issue>`
- 操作種別: `<create|update>`
- 対象番号または URL: `<number-or-url-or-none>`
- 概要欄本文ソースファイル: `<absolute-source-file-path>`
- リポジトリ: `<absolute-repo-path>`
- 適用ルール・テンプレート:
  - `<rule-or-template-file>`
- 明示的に参照すべき Issue / PR / 文書 / URL:
  - `<reference-path-url-or-none> — <why-this-reference-matters>`

## 事実情報

対象が PR の場合は PR 用の情報を埋める。対象が Issue の場合は Issue 用の情報を埋める。該当しない項目は `対象外` と明記する。明示参照は、概要欄本文の主題、判断、スコープ境界、レビュー材料との関係を確認するために優先して読む。GitHub 上で読めないローカルファイルは、投稿本文への参照先ではなくレビュー材料として扱う。

PR 用:

- 比較元: `<base-ref-or-sha>`
- 比較先: `<head-ref-or-sha>`
- コミット履歴: `<git-log-summary>`
- 差分 stat: `<git-diff-stat>`
- 変更ファイル: `<changed-files>`
- 既存タイトル・本文: `<existing-title-body-or-none>`
- 関連 Issue / PR 要約: `<related-issue-pr-summary-or-none>`
- ユーザーが明示した目的・制約・スコープ外判断: `<user-instructions-or-none>`

Issue 用:

- Issue の目的: `<issue-purpose>`
- 背景・現在の問題: `<issue-background>`
- 望ましい状態: `<desired-state>`
- 親子関係・関連 Issue / PR: `<issue-relationships-or-none>`
- ユーザーが明示した目的・制約・対象外判断: `<user-instructions-or-none>`

## 検査観点

| 観点                 | 判定基準                                                                                                                                                                |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主題との整合         | 概要欄本文が対象 PR / Issue の目的、背景、差分、関連 Issue / PR、ユーザー指示に根拠を持ち、根拠のない一般論や将来課題の羅列が含まれていないか                           |
| 背景・目的           | 読み手が変更または起票の理由、解決したい問題、選んだ方針を理解できるか                                                                                                  |
| 変更内容の意味       | 実装ファイル名、関数名、内部処理、作業手順の逐語説明ではなく、変更の意味、意思決定、利用者に見える影響、レビューすべき判断が説明されているか                            |
| PR やったこと        | `## やったこと` が存在する場合、diff の逐語説明ではなく、各変更の目的、プロダクト上の変化、意思決定、レビューすべき影響を説明しているか                                 |
| スコープ境界         | スコープ外の記述が、この PR / Issue と隣接する明確な除外判断であり、関連 Issue / PR、レビューコメント、ユーザー指示、差分上の境界から根拠を示せるか                     |
| PR やってないこと    | `## やってないこと` が存在する場合、この PR と隣接するが意図的に除外した事項だけを、関連 Issue / PR、レビューコメント、ユーザー指示、差分上の境界を根拠に説明しているか |
| 参照リンク           | References、関連 Issue / PR、外部リンクが主題、判断、スコープ境界、レビュー材料として概要欄本文中で説明できるか                                                         |
| 見出し・テンプレート | 適用テンプレートの見出しと概要欄本文が対応し、空欄、重複、矛盾、不要なセクションが整理されているか                                                                      |
| 読み手への配慮       | 変更経緯を知らない読み手が、背景、判断、影響、確認方法を概要欄本文だけで把握できるか                                                                                    |
| 適用ルール           | 対象リポジトリ、ユーザー、テンプレートで定義された概要欄本文作成ルールに合っているか                                                                                    |

## 出力形式

```text
観点別結果:
  主題との整合: OK
  背景・目的:   OK
  変更内容の意味: 要修正
    - 対象セクション: <heading>
      問題の種類: <根拠不足|実装寄り|無関係|重複|スタイル>
      該当箇所: <quote-or-summary>
      参照: <確認した Issue / PR / ファイルパス / URL>
      修正方針: <どう書き直すか>
  PR やったこと: OK
  スコープ境界: OK
  PR やってないこと: 対象外
  参照リンク:   OK
  見出し・テンプレート: OK
  読み手への配慮: OK
  適用ルール: OK
```

全観点 `OK` の場合も、PR では概要欄本文が事実情報と整合していることを明示し、`## やったこと` と `## やってないこと` が存在する場合はそれぞれ事実情報と整合していることを明示する。Issue では目的・背景・ユーザー指示と整合していることを明示する。

Issue のレビューでは `PR やったこと` と `PR やってないこと` を `対象外` として扱う。
