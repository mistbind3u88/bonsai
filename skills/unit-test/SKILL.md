# unit-test スキル

リポジトリに合わせてユニットテストを実行し、結果を報告する。タグの設置は行わない（呼び出し元の責務）。

## 手順

### 1. 実行コマンドを検出する

以下の優先順位でテストの実行コマンドを特定する。ドキュメントに記載があればそれを使い、自動検出には進まない。

#### 優先: リポジトリのドキュメント

リポジトリの `AGENTS.md`、`CLAUDE.md`、`README.md`、CI 定義、またはスキル定義にテストの実行コマンドが記載されていればそれを使う。

#### フォールバック: プロジェクトルートのファイルから自動検出

ドキュメントに記載がない場合、プロジェクトルートのファイルから推定する。

| ファイル       | 検出方法                                  |
| -------------- | ----------------------------------------- |
| `Makefile`     | `make` のターゲット一覧から `test` を探す |
| `package.json` | `scripts` フィールドから `test` を探す    |
| `Cargo.toml`   | `cargo test` を使う                       |
| `go.mod`       | `go test ./...` を使う                    |

ドキュメントにもプロジェクトファイルにも明示がない場合は言語標準のコマンドで実行する。言語標準のコマンドも特定できない場合はスキップとして扱う。

### 2. 変更範囲に応じてスコープを判定する

スコープ判定は無関係な言語のテストを省く最適化である。変更ファイルの基点を決められる場合に行い、決められない場合は省略して検出したテストをすべて実行する。

ブランチに上流（`@{upstream}`）が設定されていれば、それを基点に変更ファイルを確認する。

```bash
git diff --name-only @{upstream}...HEAD
```

変更が特定の言語やディレクトリに閉じている場合、無関係な言語のテストはスキップする。上流が未設定で基点を決められない場合は、スコープ判定を省いて検出したテストをすべて実行する。

例:

- ドキュメント（Markdown）のみの変更 → コードのテストはスキップ
- Go のみの変更 → Python 関連のテストはスキップ

変更対象の言語に対応するテストがプロジェクトに存在しない場合はスキップとして扱う。

### 3. テストを実行する

検出したコマンドでテストを実行する。

テスト実行が DB 接続など環境起因で失敗した場合は、勝手に問題なしとせず、環境の立ち上げや確認をユーザーに促す。成功を確認できていないテストをクリア扱いにしない。

### 4. 結果を報告する

テストを `PASS` / `FAIL` / `SKIP` で報告する。`FAIL` の場合は失敗したテストと要点を添える。

```
unit-test 結果:
  test: PASS
```

## 注意

- このスキルは検出と実行、結果報告のみを行う。mark タグの設置は呼び出し元（`/check` 等）が行う
- 検出できなかった場合は「スキップ」として扱い、ブロッカーにしない
