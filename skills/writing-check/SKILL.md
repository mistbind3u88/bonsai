# writing-check

エージェントが書き出したテキスト全般を、読み手に伝わる文面になっているか検査し、結果を報告する。

このスキルは、指定された本文そのものの文面品質を確認する。検査の軸は、本文の読み手、目的、根拠、行動表現、具体性、主語、粒度、構成、配置、共有範囲に置く。コード変更に対する関連ドキュメントの追従や整合の確認は、文面品質以外の不足として示す。

対象例:

- PR / Issue 本文
- PR diff comment や進捗コメント
- コードコメント、docstring
- README、手順書、設計ドキュメント、運用ドキュメント、Wiki の本文
- AGENTS.md、SKILL.md、テンプレート
- ユーザーへ提示する回答案、報告文、説明文

## 手順

### 1. 対象テキストを特定する

ユーザーが指定したテキスト、ファイル、セクション、ドラフトを対象にする。

ファイルを指定された場合は `Read` で該当箇所を読む。範囲が広い場合は、ユーザーが確認したいセクションや変更箇所を優先する。対象が曖昧な場合は、どの文章を検査するか短く確認する。

### 2. 文脈を確認する

必要に応じて、読み手、用途、共有範囲、関連する差分・Issue・PR・ユーザー指示を確認する。文脈が不明でも、分かる範囲で検査し、不足している前提は `未確認` として扱う。

### 3. 検査する

以下の観点で `OK` / `要修正` / `未確認` を判定する。

| 観点     | 判定基準                                                                                                                         |
| -------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 読み手   | 誰が読む文章かが想定され、その読み手に必要な前提が示されているか                                                                 |
| 目的     | 読み手に何を理解、判断、実行してほしいかが明確か                                                                                 |
| 根拠     | 事実、差分、Issue、PR、ログ、ユーザー指示など、確認できる根拠に基づくか                                                          |
| 行動表現 | 打ち消し表現、禁止形、責務回避の言い回しを、読み手が取るべき行動、判断、出力、確認対象へ置き換えられるか                         |
| 具体性   | 曖昧語、未定義の略語、内輪語、ジャーゴンを、読み手が理解できる定義、一般的な表現、具体的な対象へ置き換えられるか                 |
| 主語     | 誰が何を判断、実行、確認、記録するかが明確か                                                                                     |
| 粒度     | コードや差分の逐語説明、実装詳細の羅列、過剰な一般論を、読み手の判断に必要な意味、影響、制約、確認方法へ置き換えられるか         |
| 構成     | 見出し、箇条書き、順序、空欄、重複、同語反復、過剰な免責が整理され、読み手が上から順に理解できるか                               |
| 配置     | その文章に書くべき内容か、別の場所へ置くべき内容が混ざる場合は、どこへ置くべきか判断できるか                                     |
| 共有範囲 | 想定される共有範囲に対して、認証情報、秘匿情報、不要なローカルパス、個人情報、組織内情報などを本文に含めるべきか判断できているか |

`要修正` では、読み手の理解、判断、実行を妨げる具体的な問題を指摘する。どの観点で何が不足または過剰かを示す。表現の好みに留まる差分は `OK` として扱う。

### 4. 結果を報告する

次の形式で報告する。

```text
writing-check:
  対象: <text-or-file-or-section>
  読み手: OK
  目的: 未確認
    - 対象: <section-or-line>
      理由: <読み手に求める判断や行動を判定する前提が不足している>
  根拠: 要修正
    - 対象: <section-or-line>
      問題: <何が読み手の判断を妨げるか>
      修正方針: <どの根拠や説明を加えるか>
  行動表現: OK
  具体性: OK
  主語: OK
  粒度: OK
  構成: OK
  配置: OK
  共有範囲: OK
```

全観点 `OK` の場合も、上記形式で対象と各観点の `OK` を明示する。

## 注意

- 出力は、文面品質の観点別判定と修正方針に限定する。
- 文面品質以外の不足は、未確認事項または残る判断として示す。
