# writing-check サブエージェント依頼テンプレート

以下を埋めて、サブエージェントへ渡す。

## 境界確認

- 実行中のスキル: `/writing-check`
- work_unit: `writing-check:<target>`
- role: `writing-check`
- reuse_policy: `prefer-reuse`
- 依頼する役割: 対象テキストの文面品質を観点別に検査する
- サブエージェントが返すもの: 観点別の `OK` / `要修正` / `未確認` と、要修正または未確認時の理由・修正方針
- メインエージェントが担うもの: スキル進行、最終判断、ユーザー報告

## 検査対象

- リポジトリ: `<absolute-repo-path>`
- 対象: `<text-or-file-or-section>`
- ユーザーが明示した前提: `<user-provided-context-or-none>`
- 明示的に参照すべき資料:
  - `<reference-path-url-or-none> — <why-this-reference-matters>`

対象がファイルやセクションなら、そのパスや範囲を読み、対象が会話中の本文ドラフトならその本文自体を対象として読む。読み手、用途、共有範囲、関連差分、Issue / PR、ユーザー指示が明示されていれば判定材料に使い、明示されていない前提は `未確認` として扱う。

## 検査観点

| 観点     | 判定基準                                                                                                                         |
| -------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 読み手   | 誰が読む文章かが想定され、その読み手に必要な前提が示されているか                                                                 |
| 目的     | 読み手に何を理解、判断、実行してほしいかが明確か                                                                                 |
| 根拠     | 事実、差分、Issue、PR、ログ、ユーザー指示など、確認できる根拠に基づくか                                                          |
| 行動表現 | 打ち消し表現、禁止形、責務回避の言い回しを、読み手が取るべき行動、判断、出力、確認対象へ置き換えられるか                         |
| 具体性   | 曖昧語、未定義の略語、内輪語、ジャーゴンを、読み手が理解できる定義、一般的な表現、具体的な対象へ置き換えられるか                 |
| 主語     | 誰が何を判断、実行、確認、記録するかが明確か                                                                                     |
| 粒度     | コードや差分の逐語説明、実装詳細の羅列、過剰な一般論を、読み手の判断に必要な意味、影響、制約、確認方法へ置き換えられるか         |
| 構成     | 見出し、箇条書き、順序、空欄、重複、同語反復、過剰な免責が整理され、読み手が上から順に理解できるか                               |
| 配置     | その文章に書くべき内容か、別の場所へ置くべき内容が混ざる場合は、どこへ置くべきか判断できるか                                     |
| 共有範囲 | 想定される共有範囲に対して、認証情報、秘匿情報、不要なローカルパス、個人情報、組織内情報などを本文に含めるべきか判断できているか |

表現の好みに留まる差分は `OK` として扱う。文面品質以外の不足は、修正対象そのものではなく `未確認` または残る判断として示す。

## 出力形式

```text
writing-check:
  対象: <text-or-file-or-section>
  読み手: OK
  目的: 未確認
    - 対象: <section-or-line>
      理由: <読み手に求める判断や行動を判定する前提が不足している>
  根拠: 要修正
    - 対象: <section-or-line>
      問題: <何が読み手の判断を妨げるか>
      修正方針: <どの根拠や説明を加えるか>
  行動表現: OK
  具体性: OK
  主語: OK
  粒度: OK
  構成: OK
  配置: OK
  共有範囲: OK
```

全観点 `OK` の場合も上記形式で明示する。
