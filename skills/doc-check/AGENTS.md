# doc-check

## 前提ツール

- [git](https://git-scm.com/)

## 責務の境界

- `doc-check` は、コード変更に対する関連ドキュメントの整合性を検査して結果を報告する。
- 読み取り検査はサブエージェントへ限定タスクとして委譲し、起動前確認は `/subagent-check` で行う。
- 検出したドキュメント不整合の修正は `/doc-sync` に委譲する。
- LLM Wiki への反映が必要な知識は `/wiki-sync` に委譲する。
- メインエージェントは `/doc-check` の手順解釈、結果回収、最終判断、ユーザー報告を担う。

## `allowed-tools` を最小限にしている理由

検査は `general-purpose` サブエージェントへ依頼する。起動前に `/subagent-check` で既存サブエージェントの状態、起動上限の余剰、依頼文の委譲境界を確認する。このスキル自身はサブエージェントの起動、結果受領、最終判断、報告を行い、Read/Grep/Bash 等はサブエージェント側で使う。

## 記述スタイル判定基準

`SKILL.md` 手順1 の検査観点「記述スタイル」で参照する判定基準。対象は `AGENTS.md` / `CLAUDE.md` の全体と、`SKILL.md` の散文部分（手順セクションを除く）。手順セクションは「手順の正確性」観点で扱う。

## サブエージェント依頼

サブエージェントへの依頼は [subagent-prompt-template.md](subagent-prompt-template.md) を埋めて作成する。テンプレートの観点を削らず、該当しない観点は `対象外として OK` と判定させる。

新規スキルやスキル変更を検査する場合は、README の Skills 表・依存図、ルート `AGENTS.md` の分類例、スキル固有 `AGENTS.md`、`CLAUDE.md -> AGENTS.md` の反映を必ず確認する。README には発見性と全体像を置き、詳細手順・停止条件・判断基準は対象スキルの `SKILL.md` / `AGENTS.md` に置く。

### 書くこと

- 制約・禁止事項（「これをやってはいけない」「この前提を崩さない」）
- 判断基準（複数の選択肢がある場面でどちらを選ぶか）
- 背景・意図（why）・トレードオフ
- 運用・組織上の事情（コードからは見えないが作業に影響するもの）

### 書かないこと

- クラス名・関数名・ファイル構造の逐語的な列挙
- コードを読めば自明な挙動・処理の流れ
- 実装詳細のパラフレーズ
- コードコメントで十分な局所的な注意書き

### コンパクトに保つ

- 同じ内容を複数箇所で繰り返さない。一次情報源を決めて他は参照に留める
- 該当しないセクションは残さず削除する
- 例示は論点を絞る。網羅的な一覧はコード側で足りる
