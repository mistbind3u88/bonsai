# doc-check サブエージェント依頼テンプレート

以下を埋めて、サブエージェントへそのまま渡す。

## 境界確認メタ情報

- 実行中のスキル: `/doc-check`
- 依頼境界: メインエージェントが `/doc-check` を実行中であり、サブエージェントの役割は指定観点での読み取り検査結果を返すこと
- メイン側に残す判断: サブエージェント検査結果の最終判断、要修正時にユーザーへ提示する委譲先、ユーザーへの最終報告
- サブエージェントが行うこと: 対象差分と関連ドキュメントを読み、観点別に `OK` / `要修正` を返す
- サブエージェントがメイン側に残すこと: スキル実行、ファイル編集、`mark`、commit、push、ユーザーへの最終判断

## 検査対象

- リポジトリ: `<absolute-repo-path>`
- 比較元: `<base-ref-or-sha>`
- 比較先: `<head-ref-or-sha>`
- ユーザーが明示した確認範囲・変更概要: `<user-provided-scope-or-none>`
- 参照すべき判定基準:
  - `<absolute-repo-path>/AGENTS.md`
  - `<doc-check-skill-dir>/AGENTS.md`
  - `<additional-rules-if-any>`

サブエージェントは比較元・比較先の差分、変更ファイル、関連ドキュメントを読み取り、検査に必要な変更概要を自身で把握する。

## 対象ドキュメント

- `AGENTS.md` / `CLAUDE.md`
- `**/SKILL.md`
- `README.md`
- LLM Wiki（リポジトリに LLM Wiki が定義されている場合）

`archive/` 配下は退役スキルの保管場所として扱い、検査対象に含めない。

## 検査観点

| 観点                   | チェック内容                                                                                                                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 参照の有効性           | ドキュメントが参照しているファイル・スキル・コマンド・関数が存在するか                                                                                           |
| 手順の正確性           | `SKILL.md` に記載された手順が現在のコード、スクリプト、GitHub 操作、委譲先スキルと一致するか                                                                     |
| allowed-tools の過不足 | スキルが手順で使うコマンドが `allowed-tools` に含まれているか。手順で使わない許可や、他スキルに委譲する操作の許可が残っていないか                                |
| description の正確性   | スキルの `description` が現在の機能、対象場面、責務境界を正しく反映しているか                                                                                    |
| README / AGENTS 反映   | 新規・変更スキルが `README.md` の Skills 表、依存図、必要な使い分け説明、ルート `AGENTS.md` の分類例・ルールに適切に反映されているか                             |
| 情報配置の妥当性       | README は発見性と全体像に留め、詳細手順・運用判断・停止条件は対象スキルの `SKILL.md` / `AGENTS.md` に置かれているか                                              |
| 削除済みコードへの言及 | 削除・リネームされたファイル、スキル、関数、設定への参照が残っていないか                                                                                         |
| レビュー誤指摘の予防   | コードを読むだけでは誤りに見える設計判断、意図的な省略、他リポジトリとの整合などが、適切なコメントまたはドキュメントで説明されているか                           |
| LLM Wiki 反映          | リポジトリに LLM Wiki が定義されている場合、設計原則、データ契約、運用手順、互換性、下流影響、複数コンポーネントをまたぐ判断基準の変更が wiki に反映されているか |
| 記述スタイル           | `AGENTS.md` / `CLAUDE.md` と `SKILL.md` の散文部分が、コードの逐語説明や実装詳細の羅列ではなく、制約・判断基準・背景・意図・トレードオフを説明しているか         |

## 新規スキル・スキル変更時の重点確認

変更に `skills/<name>/SKILL.md` の追加・リネーム・削除・description 変更・責務変更が含まれる場合、以下を重点的に確認する。

- `README.md` の Skills 表に対象スキルが追加・更新されている
- `README.md` の依存図に対象スキルが適切な分類で追加・更新されている
- 既存スキルとの使い分け説明が必要な場合、README か関連スキルの `AGENTS.md` に発見しやすい粒度で反映されている
- ルート `AGENTS.md` の単機能 / ワークフロースキル例が現在の分類と一致している
- 対象スキルに `AGENTS.md` があり、必須セクション `## 前提ツール` と `## 責務の境界` がある
- 対象スキルに `CLAUDE.md -> AGENTS.md` のシンボリックリンクがある
- 詳細な実行手順、停止条件、判断基準は README ではなく対象スキルの `SKILL.md` / `AGENTS.md` に置かれている

## 出力フォーマット

観点別に `OK` / `要修正` を示す。`要修正` の項目は該当ファイル、抜粋または該当箇所、修正方針を添える。

```text
観点別結果:
  参照の有効性:           OK
  手順の正確性:           OK
  allowed-tools の過不足: 要修正
    - skills/example/SKILL.md allowed-tools: 手順で使わない Bash(git push:*) が残っている。push は /push に委譲する。
  description の正確性:   OK
  README / AGENTS 反映:   要修正
    - README.md Skills 表: 新規 skill example が追加されていない。Skills 表と依存図に反映する。
  情報配置の妥当性:       OK
  削除済みコードへの言及: OK
  レビュー誤指摘の予防:   OK
  LLM Wiki 反映:          OK
  記述スタイル:           OK
```

自由記述の所感は不要。全観点 `OK` の場合も、上記フォーマットで `OK` を明示する。
