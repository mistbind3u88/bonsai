# doc-check サブエージェント依頼テンプレート

以下を埋めて、サブエージェントへ渡す。

## 境界確認

- 実行中のスキル: `/doc-check`
- 依頼する役割: 対象差分に対する関連ドキュメントの整合性検査
- サブエージェントが返すもの: 観点別の `OK` / `要修正` と、要修正時の根拠・修正方針
- メインエージェントが担うもの: スキル進行、最終判断、修正方針の採否、ユーザー報告、他スキルへの委譲

## 検査対象

- リポジトリ: `<absolute-repo-path>`
- 比較元: `<base-ref-or-sha>`
- 比較先: `<head-ref-or-sha>`
- 差分 stat: `<git-diff-stat>`
- 変更ファイル: `<changed-files>`
- ユーザーが明示した確認範囲・変更概要: `<user-provided-scope-or-none>`
- 参照するルール・補足情報:
  - `<rule-or-context-file>`
- 対象リポジトリ固有の重点確認:
  - `<repository-specific-doc-check-focus-or-none>`

参照するルール・補足情報が複数ある場合は、複数行で列挙する。

比較元・比較先の差分、変更ファイル、対象リポジトリのルール、ファイル間の参照関係を読み、関連ドキュメントを特定する。対象リポジトリのルールにドキュメントの配置先、読者、目的、期待する内容が定義されている場合は、関連ドキュメントの特定と内容整合の判定材料として使う。

## 検査観点

| 観点                 | 判定基準                                                                                                                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 関連ドキュメント特定 | 変更内容に影響を受ける入口文書、手順書、設計説明、運用説明、契約説明、ルール、Wiki、対象リポジトリのルールが定義する一覧・索引・依存図・workflow 図・使い分け説明が確認対象に含まれているか |
| 変更影響の反映       | 公開挙動、API、CLI、設定、データ形式、運用、開発者 workflow、テスト方法の変更が該当ドキュメントに反映されているか                                                                           |
| 手順の正確性         | セットアップ、実行、検証、リリース、運用、復旧などの手順が現在のコード・設定・スクリプト・外部操作と一致するか                                                                              |
| 契約・互換性         | 利用者や下流に影響する契約変更について、互換性、移行、影響範囲、必要な対応が説明されているか                                                                                                |
| 参照の有効性         | ドキュメント内のファイル、コマンド、設定、リンク、Issue / PR、外部参照が現在も有効か                                                                                                        |
| 削除済み対象への言及 | 削除・リネームされたファイル、コマンド、設定、API、手順、機能への参照が現在の名称や代替手段へ更新されているか                                                                               |
| 要約・メタ情報       | ドキュメントや定義ファイルのタイトル、概要、description、対象場面、責務境界が現在の内容を反映しているか                                                                                     |
| 情報配置             | 変更説明が読み手の探す場所やコード近傍に配置されているか。ルールに定義された配置基準への適合判定は `/rule-check` に委ねる                                                                   |
| 意図の説明           | 散文が実装詳細の羅列ではなく、背景、判断基準、制約、トレードオフ、読み手が取るべき行動を説明しているか                                                                                      |
| レビュー誤指摘予防   | コードだけでは誤りに見える設計判断、意図的な省略、外部制約、他コンポーネントとの整合が必要な場所で説明されているか                                                                          |
| 知識ベース反映       | 対象リポジトリに Wiki や知識ベースが定義されている場合、設計原則、契約、運用、互換性、下流影響の変更が反映されているか                                                                      |

対象リポジトリのルールそのものへの適合、禁止表現や必須表記などのルール違反判定、コード品質ルールへの適合は `/rule-check` の担当として扱う。

## 出力形式

```text
観点別結果:
  関連ドキュメント特定: OK
  変更影響の反映:       OK
  手順の正確性:         OK
  契約・互換性:         要修正
    - ファイル: <path-or-doc-name>
      根拠: <差分・仕様・ドキュメント上の根拠>
      修正方針: <どこに何を反映するか>
  参照の有効性:         OK
  削除済み対象への言及: OK
  要約・メタ情報:       OK
  情報配置:             OK
  意図の説明:           OK
  レビュー誤指摘予防:   OK
  知識ベース反映:       OK
```

全観点 `OK` の場合も上記形式で明示する。
