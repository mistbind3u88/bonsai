# edit-taskdoc

他エージェントや将来対応のためのタスクドキュメントを、元リポジトリ側の `.claude/docs` に作成・更新する。

## 引数

```
$ARGUMENTS: <作成・更新したい内容、または対象ドキュメントのキーワード>
```

引数は、作成・更新対象の説明として扱う。削除指示として解釈してはならない。

## 対象

- 作成・更新先は元リポジトリ側の `.claude/docs` のみ
- worktree 側の `.claude/docs` には作成・更新しない
- ローカル環境に依存する固定パス（例: `~/Workspace/<repo>`）を前提にしない
- 削除や恒久ドキュメントへの移管は `/clean-docs` に委譲する

## 手順

### 1. 既存ドキュメントを確認する

まず `/read-taskdoc` を実行し、関連する既存ドキュメントがないか確認する。

既存ドキュメントがある場合は更新を優先し、同じ目的のドキュメントを重複作成しない。

### 2. 現在のリポジトリと元リポジトリを特定する

```bash
git rev-parse --show-toplevel
git worktree list --porcelain
```

`git worktree list --porcelain` の先頭に出る `worktree` を元リポジトリとして扱う。現在の作業ディレクトリが linked worktree の場合も、作成・更新先は元リポジトリ側に固定する。

元リポジトリを一意に判断できない場合は、候補パスを提示して停止する。

### 3. 更新方針を決める

以下のいずれかを選ぶ。

- **既存更新**: 関連ドキュメントがすでにあり、内容を追記・整理すれば足りる
- **新規作成**: 関連ドキュメントがなく、他エージェントや将来対応に残すべき文脈がある
- **作成しない**: プラン、Issue、PR、コミットメッセージに書くべき内容であり、タスクドキュメントとして残す必要がない

作成・更新前に、対象パスが元リポジトリ側の `.claude/docs` 配下であることを確認する。worktree 側の `.claude/docs` や、それ以外のパスが対象になっている場合は停止する。

### 4. ドキュメントを作成・更新する

`.claude/docs` が存在しない場合は、元リポジトリ側に作成する。

```bash
mkdir -p <元リポジトリ>/.claude/docs
```

新規作成する場合のファイル名は、原則として以下の形式にする。

```text
YYYY-MM-DD-<短いslug>.md
```

ドキュメントには以下を含める。

- 背景
- 現在の状態
- 決定事項
- 未解決事項
- 次に確認すべきこと
- 関連 Issue/PR
- 最終更新日

### 5. 結果を報告する

以下を報告する。

- 作成・更新した元リポジトリ側のファイルパス
- 追加・変更した要点
- 今後 `/clean-docs` で整理すべき条件

## 注意

- このスキルでは削除しない
- PR/Issue 本文からローカル `.claude/docs` を参照させない
- プランの複製、Issue/PR本文の複製、ポインタだけのドキュメントは作成しない
- 他エージェントや将来対応に必要な文脈がない場合は、作成せずにその理由を報告する
