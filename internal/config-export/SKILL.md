# config-export

実行環境のグローバル設定を読み、公開サンプルとして一般化できる内容だけを `examples/<agent>/` へ反映する。

## 対象

このスキルは、ローカルの個人設定をサンプルへ反映する。

```text
local global config -> examples/<agent> sample
```

## 手順

### 1. 対象 agent を特定する

実行中の環境、ユーザー指定、既存設定ファイルから対象 agent を決める。

| agent       | 読み取り元                                             | 反映先                                                                     |
| ----------- | ------------------------------------------------------ | -------------------------------------------------------------------------- |
| Codex       | `~/.codex/AGENTS.md`                                   | `examples/codex/AGENTS.sample.md`、必要に応じて `examples/codex/README.md` |
| Claude Code | `~/.claude/CLAUDE.md`、`~/.claude/rules/` 配下のルール | `examples/claude/README.md`、`examples/claude/rules/` 配下                 |

対象 agent を特定できない場合は、候補と根拠を示してユーザーへ確認する。

### 2. 入力と反映先を読む

ローカル設定と既存サンプルを UTF-8 として読む。読み取り時は、次を確認する。

- ローカル設定のファイル構成
- サンプル側のファイル構成
- 既存サンプルの説明粒度と見出し構成
- agent 固有の設定形式

ローカル設定が存在しない場合は停止し、見つからなかったパスを報告する。

### 3. 反映候補を分類する

ローカル設定の各見出し・箇条書き・参照を、次に分類する。

| 分類           | 意味                                                      | 次の行動                               |
| -------------- | --------------------------------------------------------- | -------------------------------------- |
| `反映可能`     | 公開サンプルとして一般化でき、対象 agent の用途に合う     | プレースホルダ化してサンプルへ反映する |
| `ローカル専用` | 個人環境、秘匿情報、社内情報、private repo に依存する     | 反映しない                             |
| `対象外`       | 対象 agent では使わない CLI、skill、設定形式に依存する    | 反映しない                             |
| `要確認`       | 一般化可能か、どの agent のサンプルに置くべきか判断が必要 | ユーザーに確認し、確認前は反映しない   |

### 4. 公開サンプル向けに一般化する

`反映可能` な項目は、公開リポジトリへ置ける形へ整える。

- 個人の絶対パスは `<path-to-...>` 形式のプレースホルダへ置き換える
- repository owner、branch、workspace 名など環境依存値は `<owner/repo>`、`<branch>` などへ置き換える
- token、API key、secret、社内 URL、内部ホスト名、個人名は削除し、ローカル設定側だけで扱う旨を必要に応じて README に書く
- 対象 agent で使わない CLI や skill 前提を、無条件のグローバルルールとして書かない
- 未導入ツール前提の運用は、条件付きの例として意味がある場合だけ明示的に条件を書く

### 5. サンプルへ反映する

既存サンプルの見出し構成に合わせて反映する。同じ趣旨の見出しがある場合は新設せず、既存見出しへ merge する。

Codex の場合は、主に `examples/codex/AGENTS.sample.md` を更新する。含める項目の一覧やローカル専用項目の説明が変わる場合は、`examples/codex/README.md` も更新する。

Claude Code の場合は、既存の `examples/claude/rules/` の役割に合わせて対象ファイルを選ぶ。新しい rule ファイルを追加する場合は、`examples/claude/README.md` の一覧も更新する。

### 6. 差分を確認して報告する

```bash
git diff -- examples
git status -s
```

報告には次を含める。

- 反映した項目
- 反映しなかった項目と理由
- ユーザー確認が必要な項目
- 書き換えたサンプルファイル

## 注意

- ローカル設定の内容をそのままコピーしない
- 秘匿情報や個人環境の値を公開サンプルへ入れない
- 対象 agent の実行環境で使わない前提を、無条件のルールとして入れない
- このスキルはサンプル更新だけを行う。ローカルのグローバル設定へ取り込む作業は `config-import` の対象とする
