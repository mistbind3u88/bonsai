# config-import

`examples/<agent>/` のグローバル設定サンプルを読み、現在の実行環境の用途に合う内容だけをローカルのグローバル設定へ merge する。

## 対象

このスキルは、公開サンプルをローカルの個人設定へ取り込む。

```text
examples/<agent> sample -> local global config
```

## 手順

### 1. 対象 agent を特定する

実行中の環境、ユーザー指定、既存設定ファイルから対象 agent を決める。

| agent       | 読み取り元サンプル                                                 | merge 先                                       |
| ----------- | ------------------------------------------------------------------ | ---------------------------------------------- |
| Codex       | `examples/codex/AGENTS.sample.md`                                  | `~/.codex/AGENTS.md`                           |
| Claude Code | `examples/claude/README.md`、`examples/claude/rules/` 配下のルール | `~/.claude/CLAUDE.md`、`~/.claude/rules/` 配下 |

対象 agent を特定できない場合は、候補と根拠を示してユーザーへ確認する。

### 2. サンプルとローカル設定を読む

サンプルと既存のローカル設定を UTF-8 として読む。

ローカル設定が存在しない場合は、サンプルから新規作成してよいかをユーザーに確認する。既存設定がある場合は、その内容を優先し、サンプル側の内容を上書き前提で扱わない。

### 3. 取り込み候補を分類する

サンプルの各見出し・箇条書き・参照を、次に分類する。

| 分類       | 意味                                                       | 次の行動                                  |
| ---------- | ---------------------------------------------------------- | ----------------------------------------- |
| `採用`     | 現在の agent と実行環境の用途に合い、既存設定と矛盾しない  | ローカル設定へ merge する                 |
| `不採用`   | 未導入ツール、別 agent、使わない skill、環境に合わない前提 | merge しない                              |
| `既存優先` | 同趣旨の既存設定があり、既存の方が環境に合っている         | 既存設定を残し、必要な補足だけ merge する |
| `要確認`   | 複数の解釈があり、採用すると挙動や承認範囲が変わる         | ユーザーに確認し、確認前は merge しない   |

### 4. 環境適合性を確認する

取り込み前に、現在の環境に合わない前提を除外する。

- インストールされていない CLI 前提を無条件で取り込まない
- 対象 agent から使わない review skill や外部 reviewer 前提を取り込まない
- サブエージェント起動などの承認方針は、ユーザーが明示起動した skill の範囲と一致するように書く
- `<path-to-...>`、`<owner/repo>`、`<branch>` などのプレースホルダを、未置換のままローカル設定へ入れない
- token、API key、secret、private repository URL、社内 URL、内部ホスト名をサンプルから取り込まない

### 5. ローカル設定へ merge する

既存設定の見出し構成を優先する。同じ趣旨の見出しがある場合は新設せず、既存見出しへ merge する。

merge では次を守る。

- 既存設定を削除する場合は、削除理由を明示してユーザーに確認する
- 矛盾するルールがある場合は自動で片方を選ばず、選択肢を示す
- ローカル固有の補足は、公開サンプルへ戻さない前提で保持する
- 書き込み先がホームディレクトリ配下の場合は、実行環境の承認ルールに従って書き込み前に確認する

### 6. 差分を確認して報告する

ローカル設定に差分を作った場合は、変更内容を確認する。Git 管理外のホーム配下ファイルは `git diff` で確認できないため、変更前後の要約または一時差分を使って報告する。

報告には次を含める。

- 採用した項目
- 不採用にした項目と理由
- 既存設定を優先した項目
- ユーザー確認が必要な項目
- 書き換えたローカル設定ファイル

## 注意

- サンプルを丸ごとコピーしない
- 既存のローカル設定を無断で削除しない
- 実行環境に存在しない CLI や skill 前提を無条件で取り込まない
- このスキルはローカル設定への取り込みだけを行う。ローカル設定から公開サンプルへ反映する作業は `config-export` の対象とする
