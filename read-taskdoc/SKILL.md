# read-taskdoc

元リポジトリ側の `.claude/docs` に配置されたタスクドキュメントを検索・参照する。

## 引数

```
$ARGUMENTS: <検索キーワードまたはドキュメントパス（任意）>
```

引数があれば、ブランチ名・Issue/PR番号・ファイル名・本文キーワードとして絞り込みに使う。引数がなければ、現在のブランチ名と直近の作業文脈から関連しそうなドキュメントを探す。

## 対象

- 対象は元リポジトリ側の `.claude/docs` のみ
- worktree 側の `.claude/docs` は参照対象にしない
- ローカル環境に依存する固定パス（例: `~/Workspace/<repo>`）を前提にしない

## 手順

### 1. 現在のリポジトリと元リポジトリを特定する

```bash
git rev-parse --show-toplevel
git worktree list --porcelain
```

`git worktree list --porcelain` の先頭に出る `worktree` を元リポジトリとして扱う。現在の作業ディレクトリが linked worktree の場合も、参照対象は元リポジトリ側に固定する。

元リポジトリを一意に判断できない場合は、候補パスを提示して停止する。

### 2. `.claude/docs` の存在を確認する

元リポジトリ側の `.claude/docs` を対象にする。

存在しない、または空の場合は「関連するタスクドキュメントはありません」と報告して終了する。

### 3. 関連ドキュメントを探す

以下の順で関連候補を探す。

1. `$ARGUMENTS` と一致するファイル名・ディレクトリ名
2. `$ARGUMENTS` と一致する本文
3. 現在のブランチ名と一致するファイル名・本文
4. ブランチ名から推定できる Issue/PR 番号と一致する本文

候補が複数ある場合は、ファイルパスと一致理由を一覧にしてから必要なものだけ読む。

### 4. 内容を要約する

読んだドキュメントについて以下を報告する。

- ファイルパス
- 対象タスク・関連 Issue/PR
- 現在の状態
- 決定事項
- 未解決事項・次に確認すべきこと

## 注意

- このスキルではファイルを作成・更新・削除しない
- タスクドキュメントの作成・更新が必要な場合は `/edit-taskdoc` に委譲する
- 完了済みドキュメントの削除や恒久ドキュメントへの移管は `/clean-docs` に委譲する
