# Codex Global Settings Sample

このディレクトリは、Codexのグローバル指示に採用する運用方針のサンプルを管理します。`AGENTS.sample.md` はこのリポジトリへ自動適用する設定ではありません。

## 適用方法と設定の役割

1. `AGENTS.sample.md` を読み、必要な方針だけを選ぶ。リポジトリ固有の手順は、そのリポジトリの指示やスキルへ置く。
2. `CODEX_HOME` の実際の配置先を確認する。通常は `~/.codex` で、グローバル指示はその配下の `AGENTS.md` に置く。`AGENTS.override.md` がある場合はそちらが優先されるため、実際に読まれるファイルを確認する。
3. 既存内容と差分を確認して反映し、新しいセッションで読込を確認する。リポジトリ内の指示は、プロジェクトルートから作業ディレクトリまでの階層も確認する。
4. 秘密情報、非公開URL、個人の絶対パス、実際の環境設定は公開サンプルへ書かず、適切なローカル設定や認証手段で扱う。

`AGENTS.md` は自然言語の作業指示です。モデル、sandbox、承認方式などの実設定は `config.toml` や管理ポリシーが制御します。指示文に承認済みと書いても実行権限は増えません。`model_instructions_file` は組み込み指示を置き換える設定であり、追加のグローバル指示を置くための代替ではありません。

参照: [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[Configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference)。

## 個人の運用方針として選ぶ項目

次は公式の一律の既定動作ではなく、このサンプルで選んだ運用方針です。

- スキルの明示起動を、その標準手順に対する作業範囲の承認として扱うこと
- サブエージェントを明示依頼またはスキルの明示要求に限って使うこと
- サブエージェント依頼の `work_unit`、`role`、`reuse_policy` を使うこと
- 指定がない場合の作業ブランチ、日本語のコミット件名、番号なしのMarkdown見出し
- 必須チェックの省略条件、完了判定、レビュー記録の運用

採用先のユーザー方針、リポジトリの指示、スキルの停止条件、実行時のツール方針と照合して調整してください。自動的な権限審査も、作業の委譲や公開範囲に対するユーザー承認とは別です。

## 環境固有の補足

ここは必要な環境だけで採用する設定候補です。実際の導入状況とパスを確認し、必要ならローカル指示へ移してください。

### Windowsのリンクとshell script

- シンボリックリンクが必要な場合は、PowerShellの `New-Item -ItemType SymbolicLink` で作成し、権限エラーなら現在の環境で許可された別の作成方法を確認する。`cmd /c mklink` を使う場合も、必要な権限が満たされることを確認する。コマンドの変更だけで権限が得られるとは扱わない。
- 作成後はリンク種別と参照先を確認し、Gitで追跡する用途の場合はリンク自体の差分を確認する。`CLAUDE.md` のリンクが必要かどうかは採用先のツール仕様とリポジトリ方針で判断する。
- POSIX shell用scriptは、scriptとshellの実体を確認し、PowerShellでは `& "<path-to-git>/bin/sh.exe" "<script-path>"` のように外側から呼び出す。実行報告には使ったshell実体と外側実行であることを記載する。

### Formatterとbonsaiの補助コマンド

- グローバルPrettierが利用可能で、リポジトリの設定と互換な場合は `prettier` を直接利用できる。再現性の基準はリポジトリローカルの設定・依存関係とする。
- bonsaiの補助コマンドを使う場合は、利用するshellの `PATH` に `<path-to-skills-repo>/tools` を追加し、コマンドが解決できることを確認する。設定はshell側で行い、公開サンプルには個人の絶対パスを含めない。
- スキル定義の `allowed-tools` やPATH上のコマンドの書き方は、対象ツールと採用先のスキル作成規約に従う。これをCodex全体の実行許可とは扱わない。
